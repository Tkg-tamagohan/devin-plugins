# 子セッションへの並列実装の分割と依頼

並列で動く子セッション同士はファイルシステムを共有しないが、同じリポジトリの trunk に向かって PR を出す。
同じファイルを直す変更が二つのトラックにまたがると、マージ競合とレビューの混乱が起きる。
競合しない分割を先に設計してから子セッションを起こす。

## 手順

1. 実施したい変更群が触るファイルを列挙し、同一ファイルを触る変更は同一トラックに集約する。
2. 他トラック所有のファイルを変更せずに済むか検討し、避けられない呼び出しは公開シグネチャを維持したファサード化（薄い委譲層の追加）で吸収する指定を計画に入れる。
3. 各トラックを一つの子セッションに割り当て、次の定型でプロンプトを書く。
   - 目的と背景（なぜこの変更か）
   - 作業内容（変更の範囲）
   - 排他ファイル境界（変更してよいファイル、変更してはいけないファイルを明示）
   - 完了条件（build/test 全パス、`devin/$(date +%s)-<slug>` ブランチ、日本語 PR、CI 確認）
   - 競合時の対応（兄弟 PR が先にマージされて競合したら、最新 origin/main へリベースして自分の担当ファイルに限り競合を解消する）
4. 全子セッションの PR が揃ったら、対応しなかった指摘や先送りした事項を、先送り理由と再検討条件（実害発生時など）を付記した残課題文書にまとめる。

## 運用上の注意

- **同時起動スロット**：この組織の SWE-2 無料枠は執筆時点（2026-10）で同時 5 セッション（親を含む）までで、超過分のセッション作成は HTTP 429 で即失敗する。
  - 枠の値はプロモーションやプランの変更で変わりうるため、429 が出たら現行の上限を確認する。
  - アイドルや完了済みの子も suspend するまでスロットを占有し続けるため、完了した子を `devin_session_interact(action="sleep")` で寝かせてから次を起こす。
  - 前フェーズの子が残ったまま次フェーズを始めると 429 になるので、フェーズの切り替わりで不要な子を寝かせる。
- **子への自己 sleep 指示**：完了条件の最後に自己 sleep を指示すると structured output は記録されるが、ワークフローの `agent()` は執筆時点の挙動では `settled without finishing (status=suspended)` で失敗扱いになる。
  - 成果物自体は完成しているので `run_id` で resume して同じ agent を再実行しない（重複 PR ができる）。
  - 出力は `devin_session_interact(action="get")` の `structured_output` で回収する。
- **直接起動のフォールバック**：429 で失敗した残トラックは `devin_session_create` で直接起こしてよい。
  - ワークフローの外でも起動でき、スロットが空き次第すぐ再開できる。
- **起動直後の run 失敗**：スクリプトの構文ミスで run が起動直後に failed したときは、修正して新規 run を作る。
  - 完了済み agent の結果は resume でリプレイされる。
- **子の連続キャンセル**：同じトラックの子が連続してキャンセルされたときは、再起動を繰り返さず worktree の成果物を点検して親が直接実装する経路に切り替える。
  - 親のブロッキング待機が中断されると子の実行も巻き込まれて止まる観察があるため、対話を重ねるセッションでは起きやすい（推測）。
  - 2 連続で同じ失敗形が出た時点を切り替えの目安とする。
- **PR 本文は `--body-file` で渡す**：子に `gh pr create` を指示するときは、インライン `--body` ではなく `--body-file` を使わせる。
  - `--body "..."` のダブルクォート内に書いたバッククォートはシェルのコマンド置換として解釈され、PR 本文からコード片が消えた実害があった。

## 原則

- 「この子だけが触る」集合が重ならないことが並列化の前提であり、分割は機能ではなくファイル所有で行う。
- 子プロンプトの境界指定が曖昧だと、子が隣接ファイルに手を出して競合する。
- スキル改善提案など作業 PR と別種の成果物は、作業 PR に混ぜず専用の PR で取り込む。
