# 子セッションへの並列実装の分割と依頼

並列で動く子セッション同士はファイルシステムを共有しないが、同じリポジトリの trunk に向かって PR を出す。
同じファイルを直す変更が二つのトラックにまたがると、マージ競合とレビューの混乱が起きる。
競合しない分割を先に設計してから子セッションを起こす。

## 手順

1. 実施したい変更群が触るファイルを列挙し、同一ファイルを触る変更は同一トラックに集約する。
2. 他トラック所有のファイルを変更せずに済むか検討する。避けられない呼び出しは、公開シグネチャを維持したファサード化（薄い委譲層の追加）で吸収する指定を計画に入れる。
3. 各トラックを一つの子セッションに割り当て、次の定型でプロンプトを書く。
   - 目的と背景（なぜこの変更か）
   - 作業内容（変更の範囲）
   - 排他ファイル境界（変更してよいファイル、変更してはいけないファイルを明示）
   - 完了条件（build/test 全パス、`devin/$(date +%s)-<slug>` ブランチ、日本語 PR、CI 確認）
   - 競合時の対応（兄弟 PR が先にマージされて競合したら、最新 origin/main へリベースして競合を解消する。解消は自分の担当ファイルに限る）
4. 全子セッションの PR が揃ったら、対応しなかった指摘・先送りした事項を残課題文書にまとめる。残課題には先送り理由と再検討条件（実害発生時など）を付記する。

## 運用上の注意

- **同時起動スロット**：この組織の SWE-2 無料枠は同時 5 セッション（親を含む）までで、超過分のセッション作成は HTTP 429 で即失敗する。アイドル・完了済みの子も suspend するまでスロットを占有し続けるため、完了した子を `devin_session_interact(action="sleep")` で寝かせてから次を起こす。前フェーズの子が残ったまま次フェーズを始めると 429 になるので、フェーズの切り替わりで不要な子を寝かせる。
- **子への自己 sleep 指示**：完了条件の最後に自己 sleep を指示すると structured output は記録されるが、ワークフローの `agent()` は `settled without finishing (status=suspended)` で失敗扱いになる。成果物自体は完成しているので `run_id` で resume して同じ agent を再実行しない（重複 PR ができる）。出力は `devin_session_interact(action="get")` の `structured_output` で回収する。
- **直接起動のフォールバック**：429 で失敗した残トラックは `devin_session_create` で直接起こしてよい。ワークフローの外でも起動でき、スロットが空き次第すぐ再開できる。
- **起動直後の run 失敗**：スクリプトの構文ミスで run が起動直後に failed したときは、修正して新規 run を作る。完了済み agent の結果は resume でリプレイされる。

## 原則

- 分割は機能ではなくファイル所有で行う。「この子だけが触る」集合が重ならないことが並列化の前提である。
- 子プロンプトの境界指定が曖昧だと、子が隣接ファイルに手を出して競合する。
- スキル改善提案など作業 PR と別種の成果物は、作業 PR に混ぜず専用の PR で取り込む。
