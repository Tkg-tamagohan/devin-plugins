# AI 生成文の不自然な語彙・構文カタログ

本カタログは、日本語 LLM 特有の不自然な語彙・構文パターンをまとめた辞書である。
`slop_lint.py` の機械検査や、文書の推敲で表現を見直すときに参照する。
修正方針の候補は機械的な置換表ではなく、原文と文脈で状態の種類・強さ・対象範囲が同じになると確定できる場合だけ使う。
意味が同じと確定できない語を近い語へ安易に言い換えず、言い換えられない場合は元の表現を残す。
文脈上正当な専門用語(医学の「体温」、画像処理の「解像度」、化学の「触媒」など)であれば、無理に言い換えず保持する。

## 1. AI 偏愛動詞・比喩動詞

抽象的な事象や技術操作を、安易な比喩動詞で言い換える傾向を解体する。
なお、「骨が折れる」「手を焼く」「目から鱗が落ちる」のようなふだんの日本語で定着した慣用句は、AI っぽい比喩として扱わず残す。
目安は、AI が広まる前の人の文章でもその言い方を見かけるかどうかである。

| AI 偏愛動詞 | AI 特有の用例 | 自然な表現への修正方針 |
|---|---|---|
| **効く / 効いてくる** | 「地味に効きます」「〜が効いてくる」 | 「〜の役に立つ」「効果がある」「〜を防げる」(「地味に」の目立たなさの含みは「目立たないながらも役に立つ」などで残す) |
| **壊れる** | 「データが静かに壊れる」「設計が壊れる」 | 「おかしくなる」「使えなくなる」など、元の語と同じ広さの意味を持つ語を優先する。「要件を満たせなくなる」「例外が出る」「整合性が崩れる」のような限定した書き方は、前後からその話と明らかなときに限る。時計や機械など文字どおりの「壊れる」は残す |
| **倒す** | 「〜側に倒す」「残さない側に倒す」 | 「〜を原則とする」「除外する」「〜を採択する」 |
| **溶かす** | 「時間を溶かしました」 | 「多くの時間を費やした」「調査に時間がかかった」 |
| **潰す** | 「1つずつ潰していく」 | 「エラーを1件ずつ解消する」「原因を1つずつ検証する」 |
| **踏み込む** | 「〜まで踏み込んで」「内部実装まで踏み込む」 | 「〜の詳細まで具体的に調べて」「〜の内部実装まで確認して」 |
| **引き返す** | 「動かしながら引き返す」 | 「元の状態に戻す」「ロールバックする」 |
| **添える** | 「経路が代わりに添える」 | 「参照する」「付与する」「渡す」 |
| **収斂する** | 「その価格帯に収斂した」「議論が収斂する」 | 「〜に決まった」「〜に落ち着いた」 |
| **沈黙する** | 「静かに沈黙する」 | 「エラーを出さずに終了する」「応答しない」 |
| **黙って** | 「黙って無視される」「黙って捨てられる」 | 「通知なく破棄される」「ログを出さずにスキップする」 |
| **崩れる・醸成・定着(非生物主語)** | 「前提が崩れる」「基盤が崩れる」「文化が醸成される」「プロセスが定着する」「事例が残した」 | 「成り立たなくなる」「広まる」「根付く」 |
| **逃がす** | 「例外を上に逃がす」「処理を別のスレッドに逃がす」 | 「呼び出し元へ渡す」「別のスレッドへ移す」。何をどこへ移すのかが原文や前後から分かる場合だけ、その動作で書く。分からない場合は元の動詞のまま残す。「熱を逃がす」「魚を逃がす」のような字義どおりの用法は残す。 |

## 2. 英語直訳調・統語リーク

英語表現を直訳した結果生じる不自然な構文を平文化する。

| 英語の原表現 | AI の直訳日本語 | 自然な日本語 |
|---|---|---|
| *silently fail / ignored* | 「静かに壊れる」「黙って無視される」 | 「エラーを出さずに失敗する」(元の意味が silently fail だと確定した場合の限定した書き方の例)、「警告なしで無視される」 |
| *the moment ...* | 「〜した瞬間」「〜した瞬間に」 | 「〜するとすぐに」「〜した直後に」「〜した時点で」 |
| *single source of truth* | 「〜を正本にする」「〜の正本として」 | 「信頼できる唯一の情報源とする」「マスターデータとする」 |
| *point to / suggest* | 「〜を指している」「〜を示唆している」 | 「〜を表している」「〜と考えられる」「〜を意味する」 |
| *load-bearing* | 「耐力のある」「構造を支える」 | 「不可欠な」「根幹となる」「外せない」 |
| *it is not X, it is Y* | 「Xではなく、Yです」「Xではない。Wでもない。Yだ。」「Xじゃない、Yです」「単なるXではなく、Yです」 | 「Xではなく、Yでもある」は否定と「も」を保って一つの文のまま残し、2文に分けたり、その意味を書き手に尋ねたりしない。単なる修辞でXを削っても通じる場合は「Yです」とする。Xと誤解されやすい点への反論や見方の切り替えを担っている場合は、否定を残して「Xではなく、Yです」と自然に整える(Aに加えてBなどに改変しない。「そのもの」等の余計な強調語は足さない)。否定を重ねる形も同じ基準で判断し、否定を残す場合は否定していた内容をすべて保つ。直前で問いなどとして挙げた二つを否定が打ち消すだけで、「どちら」が何と何を指すかが直前の文脈から一通りに決まる場合は、「どちらでもない。」(敬体なら「どちらでもありません。」)と短く受けてもよい。打ち消すほかに問いにない内容を含む否定は短くしない。 |
| *closure* | 「依存の閉包」「〜の閉包を取る」 | 「そこから参照されるものすべて」「依存しているものを全部」のように何を集めたものかを書く。数学(推移閉包、閉包演算など)や言語仕様のクロージャ(closure)を定義どおり使う場合は残す。 |
| *delve into* | 「〜に深く分け入る」「深掘りする」 | 「詳しく調べる」「具体的に見ていく」 |
| *em dash (— / ―)、罫線 (─ / ━ / ──)* | 「〜――とりわけ〜――は」、「速さ、軽さ、静けさ──。」 | 「〜、特に〜は」のように、対象と強調する範囲を保って句読点や助詞でつなぐ。末尾で余韻を持たせる列挙は「速さと軽さ、静けさを重視しました。」のように何についての列挙かを述語で言い切る。文脈から述語が分からない場合は推測で補わず、記号だけ外して並びを残し、書き手に確認する(小説・随筆で文体として使うダッシュや引用は残す)。 |

## 3. 急増した比喩・評価名詞

AI 普及以後の技術文書で急増した比喩・評価名詞を解体する。

| 分類 | 語彙 | AI 用例 | 修正方針 |
|---|---|---|---|
| **障害・失敗の比喩** | `事故` `混ざる` `落とし穴` `破綻` `実害` `素通り` | 「〜という事故」「落とし穴があります」 | 「不整合」「例外発生」「考慮すべき点」 |
| **確認・検証の比喩** | `実測` `疑う` `照合` `突き合わせる` `断定` `取り違える` `見落とす` | 「実測では」「〜を取り違えると」 | 「計測値」「確認する」「比較検証する」「気づかない・確認から漏れる」 |
| **役割・位置の比喩** | `入口` `土台` `道具` `核心` `主役` `構図` `線引き` `営み` `装置` `羅針盤` `起爆剤` `触媒` `導線` `出口` `〜のカギ` `〜への近道` `〜の第一歩` `両輪` | 「〜の入口として」「〜するための土台」 | 「導入」「前提条件」「基礎知識」。電気の導線、建物の出口、出口戦略のような字義どおりの用法や定着した用語は残す。 |
| **評価・結論の定型** | `既定` `別物` `定番` `要点` `定石` `桁違い` `勝ち筋` `刺さる` `〜で決まる` | 「既定では」「〜とは別物です」 | 「初期設定では」「性質が異なります」。何によって何が決まるのかが原文から分かる場合だけそれを書く。 |

## 4. 必殺技造語・体験の壮大化

個人のささやかな体験や日常的な技術判断を、重厚な熟語で大げさに語る傾向を排除する。

| 壮大化熟語群 | AI の典型的な不自然な記述 | 自然な表現 |
|---|---|---|
| `真理` `真実` `結末` `宿命` `運命` `境地` `極致` `究極` `虚飾` `虚像` `美学` `深淵` `禁欲的` `優美` `冷徹` `残酷` `凝縮` `結晶` | スペックという虚飾を剥ぎ取った時、指先が感知した真実とは。 | 3年使いましたが、REALFORCE は打鍵感が柔らかすぎると感じ、私は HHKB のほうが好みでした。 |

個人の日常や業務エピソードに、普遍の教訓を不自然に付加しない方針をとる。

## 5. 質感を装う疑似具体語・ビジネスジャーゴン

一見プロっぽく見えるが、中身が何もない空虚なキーワードを排除する。

| 分類 | 対象語彙 | 是正ルール |
|---|---|---|
| **質感を装う語** | `手触り` `肌感` `肌感覚` `体温` `温度感` `熱量` `血の通った` `泥臭い` `泥臭さ` | 実際に操作した手順、ログ、実測値を具体的に書く。 |
| **認知を装う語** | `解像度`(解像度を上げる/高い) `腹落ち` `メンタルモデル` `文脈` `粒度` `余白` `軸` `言語化` | その語が指す考えや前提を、元の文にある情報の範囲で説明する。データの粒度や座標軸のような技術用語、紙面の余白のような字義どおりの用法は残す。 |
| **作業を曖昧に表す動詞** | `落とし込む` `紐解く` | 何をどうするのか(手順にする、資料にまとめる、原因を調べるなど)が原文から分かる場合だけ、その動作で書く。分からない場合は動作を推測で決めず、元の語を残す。「歴史を紐解く」のように書物や記録を読み解く意味で使う定着した言い方は残す。 |
| **評価を装う語** | `本質` `本質的` `地に足のついた` `等身大` `これは強い` | 空疎な修飾を削り、客観的な事実のみを書く。「これは強い」は、何に有効かが原文から分かる場合だけ「〜に有効だ」のように書く。 |
| **未定義造語** | `意思決定OS` `思考のOS` `仕事のOS` などの勝手な比喩命名 | 標準的な技術用語または機能説明で書く(硬い漢語を並べない)。 |
| **形で確かめる語** | `閉包` `本質を突く` | 文脈上正当な用語(数学の推移閉包・閉包演算など)は保持する。比喩や大げさな装飾として使う場合は具体的な表現に書き直す。 |
| **役割を大げさに呼ぶ語** | `契約` `正本` `ゲート` `台帳` | 「ルール」「方針」「原文」「比較の基準」「参照するファイル」「確認」「チェック」「記録」「一覧」など、実際の役割に合う語へ直す。取引や合意としての契約、正式文書を区別する正本、品質ゲートや改札・搭乗のような字義どおりの用法、会計・行政の台帳、定義済みの専門用語は保持する。 |
| **指す内容が曖昧な名詞** | `仕組み` `境界` | 何を行うか、何を区別するかが分かる範囲で書く。実際の処理を説明する「仕組み」や、数学・区域の境界、境界値、定義済みの用語や実際の名称は保持する。 |

## 6. メタ宣言・時間稼ぎフィラー

読者の感情や理解度を先回りしてコントロールしようとする無駄な前置きや後置句を削除する。

| 分類 | 対象表現 | 是正ルール |
|---|---|---|
| **前置フィラー** | `重要なのは` `大切なのは` `結論から言うと` `結論から言うね` `結論から言います` `正直に言うと` `本音を言うと` `原因はシンプルです` `避けたいのは` `ポイントは、` `ここで注目すべきは` `ここが一番見落とされがち` `まさにそこがポイント` `もちろん、〜。` | 単なる前置きは削る。評価は述語へ移して保つ。理由・対比・結論や文の働きの切替を示す場合は、その関係を残す。文頭の「もちろん、」のあとに数語だけが続く短い文は、問いや依頼への答え、条件や前提の確認、会話や引用なら残す。 |
| **定型導入** | `本記事では〜をご紹介します` `それでは見ていきましょう` `深掘りしていきます` `ここまで見てきました` | 続く本文と同じ内容を予告したり振り返ったりしているだけの案内は削る。長いマニュアルの目次的な案内や、扱う範囲・前提・対象読者を示す文は残す。 |
| **数の宣言** | `重要なポイントは3つです` `理由は3つあります` `以下の3つの観点から説明します` | 宣言の数と続く項目の数が合っている場合だけ、続く中身とまとめるか宣言を削る。長い説明で、項目数の予告が読み手の案内になっている場合は残す。数が合わない場合も、宣言の数と項目を変えない。 |
| **文末の付け足し** | `〜というわけです` `〜に他なりません` `〜と言えるでしょう` `面白いのはここです` `見落とされがち` `驚くべきことに` | 文末を断定(〜である、〜です)または事実記述で閉じる。 |
| **言い直しの締め** | `まとめると、` `総じて、` `結局のところ` `要するに`、本文の繰り返しだけの「まとめ」見出しと段落(`## まとめ`) | 本文で言い終えた内容を同じ強さで繰り返すだけなら、その文や段落、見出しを削る。新しい情報、条件、結論の絞り込み、長い文書の要約を担う場合は残す。その箇所にしかない数値・条件・例外は落とさない。 |
| **チャット応答の名残** | `ご質問ありがとうございます` `おっしゃる通りです` `必要なら次に〜します` `ご希望があれば〜できます` `〜を知りたいですか？` | 記事や文書の本文に、チャットの返答の書き出しや申し出、同意・共感の定型が残っている場合は削る。チャットの返信そのものを推敲する場合や、書き手が読者に実際に申し出ている場合、会話・引用は残す。 |
| **定型の結び** | `いかがでしたでしょうか` `ぜひ試してみてください` `ぜひ参考にしてください` `〜の参考になれば幸いです` `お役に立てば幸い` `ぜひご活用ください` `まずは小さく始めましょう` | 意味を担わない定型の呼びかけを削り、本文の自然な結びで終わる。メールや手紙の結びの挨拶、書き手が実際に勧めている内容は残す。 |
| **見直し候補の文型(info)** | `ポイントは3つです` `もちろん、失敗もする。` `速い。軽い。安い。` `- **項目**: 説明` `車でも、家でもない。有頂天だ。` `これは努力じゃない、仕組みです` | リントは警告ではなく情報(info)として出す。繰り返しや装飾であれば削る。要約・確認・答えとして意味を担う場合、出典や区間など正当な用途は残す。 |

## 7. 硬い漢語と決まり文句

文章を硬く、型にはまった印象にする漢語や決まり文句を見直す。

| 分類 | 見直したい表現 | 書き直すときの注意点 |
|---|---|---|
| **硬い漢語** | `活用する` `実施する` `多角的` `包括的` `〜を実現することができます` | `活用する`→「使う」(生かすという含みが要る場合は「生かす」)、`実施する`→「行う」「する」、`〜を実現することができます`→「〜できます」。`多角的` `包括的` は、どの観点やどの範囲で見るのかが原文から分かる場合だけ、その観点や範囲を書く。分からない場合は観点を推測で足さず、元の語を残す。 |
| **決まり文句** | `シームレス` `シナジー` `価値を最大化` `次のレベルへ` | 何がどう変わるのかが原文から分かる場合だけ、その内容で書く。分からない場合は効果を推測で足さず、元の語を残す。製品の機能名や定義された用語は残す。 |
| **誇張語** | `圧倒的` `爆速` `革命的` `徹底解説` | 数値の裏付けがある場合や、書き手の実感として書いている場合は残す。本文の内容と釣り合わない誇張だけを、評価の向きを保ってふだんの言葉にする。元にない数値や比較を足さない。 |

## 8. lint の info 規則が拾う文の形と言い回し

語彙ではなく文の形や決まった言い回しを見る info 規則をまとめる。info の候補は `--strict` と `--fail-on` の条件に入らない(点数 `rule_penalty_score` への算入は規則ごとに異なり、上流 2.2.0 以降の見直し規則の候補は除かれる。詳細は `slop-lint-usage.md`)。見直しのきっかけであって当たっただけでは直さない。直すか残すかは、意味・強さ・対象が元と同じになるかで判断する(1章の方針と同じ)。直訳語の型と例は `calques.md`、thin-evaluation・katakana-terms・renyo-nouns の一覧は `lists/` を参照する。

| 規則 | 型・言い回し | 例 | 見直すときの注意 |
|---|---|---|---|
| `ai_phrase` | 文末の「〜という見立てです」 | 「今回の結果は、市場が回復に向かうという見立てです。」 | 誰の判断かが分かる文にする(「担当者の見立てでは」など)。判断した人や組織が原文になければ推測で足さない |
| `ai_phrase` | 「問題が潜む」「〜に潜む」 | 「この設定には、いくつかの落とし穴が潜んでいます。」 | 潜むものの中身を具体的に書く。動物や虫が潜む文は対象外 |
| `ai_phrase` | 「〜が招く」に名詞が続く形 | 「この油断が招く失敗を防ぐために、手順を見直しました。」 | 何を招くかを書く。人や組織が客などを招く文は対象外 |
| `ai_phrase` | 「今や〜欠かせない存在」「欠かせない存在となっています」 | 「今やログの出力は欠かせない存在です。」 | 誰にとって何のために要るかを書く |
| `ai_phrase` | 「という挙動を排除(防止・阻止)」 | 「この変更は、例外処理という挙動を排除します。」 | 何をどうするかを述語まで書く |
| `ai_phrase` | 地の文の文末の「なんよ」「なんよね」 | 「この機能は本当に便利なんよ。」 | 文末のくだけた語尾。語りかけの相手や文体に合わなければ文末を整える |
| `ai_phrase` | 「〜して、〜を＋漢語の名詞。」の体言止め | 「設定を見直して、速度を改善。」 | 何をどうしたかを述語まで書く |
| `calque` | 型1: 機械やシステムが人の動作をする言い方 | 「取りこぼした通知は、翌朝の再送ジョブが拾います。」 | 型と例は `calques.md`。語の差し替えではなく文として書き直す |
| `calque` | 型2: 実物の名前の代わりの場所のたとえ | 「社外からの接続は、この入口を通ります。」 | 同上 |
| `calque` | 型3: 英語を一語ずつ写した句 | 「この層で変換しても、足すものがありません。」 | 元の英語の言い方の意味で書き直す |
| `metaphor_label` | 見出しや1行目の、本文に出てこない一語の比喩 | 「数え係」 | 本文の語で項目名を作る。文書の題は変えず、読めなければ書き手に確かめる |
| `say_hedge` | 文末の「〜と言えるでしょう」 | 「7月以降の増加は、定期便の開始が主な原因だったと言えるでしょう。」 | 推量の「でしょう」を残して「と言える」だけを外す。「と言える」への置き換えや断定にはしない |
| `thin_evaluation` | 名詞がもともと持つ評価を述語で言い直すだけの文 | 「委託先の回答の品質も高いです。」 | 前後に評価の中身(数値・素材など)があれば事実の文に寄せる。一覧は `lists/thin-evaluation.txt` |
| `katakana_term` | 意味の薄くなりやすいカタカナ語 | 「顧客とのエンゲージメントを高めることも課題です。」 | 何をどうするかが分かる言葉にする。一覧は `lists/katakana-terms.txt` |
| `renyo_noun` | 他動詞の連用形を1語だけ名詞にして「の」で受ける形 | 「出した数字は、表の値との確かめが済んでいません。」 | 「結果を確かめる」か定着した漢語(結果の確認)にする。一覧は `lists/renyo-nouns.txt` |
| `copy_comma_noun` | 修飾語と名詞のあいだに読点を打ち、短い名詞で止める形 | 「丁寧な、人。」 | キャッチコピー調の修辞。文として書き直す |
| `bare_verb_chain` | 主語も目的語もない他動詞を読点で並べて止める文 | 「切るか、続けるか、決める。」 | 誰が何をするかを書く |
| `pause_comma` | 短い主題・主語・目的語のすぐあとの読点 | 「受付の窓口には、来月から一人増やします。」 | 間を作るだけの読点は外す。誤読を防ぐ所、長い主語や節の切れ目、並べ、条件・逆接・理由の切れ目の読点は残す |
| `cleft_list_ending` | 「〜のは、」のあとに名詞を並べ、述語で言い切らない文 | 「書き換えの中で変動したのは、画面、帳票、通知。」 | 「のは」の前の動詞を述語に戻す。前提がある場合や強調として選んだ形は残す |
| `instruction_residue` | AIへの指示や除外の判断が本文に残った文 | 「今回は一般論ではなく、自分の体験に絞って紹介します。」 | 除外や書き方の方針を述べる文を削る。読者のための範囲・対象読者・前提・参照先を示す文は残す |

文書単位で1件ずつ出る info 規則として、`dialogue_period`(台詞の最後の句点の割合)と `narrative_density`(一人称の少なさと数字・箇条書きの密度)がある。個々の表現ではなく文書全体の書き方を見直す合図である。プロジェクトの語の一覧(`.yomiyasu-words/`)では、flag.txt と flag-patterns.txt の語やパターンに `project_term` が出て、直訳語と同じく文として書き直す対象とする。allow.txt の語は指摘を外すために使う(3つのファイルの使い方は `slop-lint-usage.md`)。
