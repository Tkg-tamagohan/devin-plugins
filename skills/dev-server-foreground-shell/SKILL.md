# Devin VM での開発サーバー運用

開発サーバーは `exec` の `shell_id` を持つフォアグラウンドシェルで起動し、その shell_id を使い回して管理する。
`nohup` や `setsid` でデーモン化すると、起動直後に落ちたとき原因の切り分けが難しく、止める操作が自分のコマンド列を巻き込む事故が起きる。

## 手順

1. `exec` に `shell_id: "app<ポート番号>"` のような専用名を付け、サーバーをフォアグラウンドで起動する（例：`dotnet run --project ... --urls http://127.0.0.1:5180`）。
2. 起動したら `browser_preview` で同じポートを公開する。
3. ログを見るときは `get_output` を同じ shell_id に対して呼ぶ。サーバーは動かしたままにする。
4. 止めるときはそのシェルを `kill_shell` する。コマンド列のパターンでプロセスを殺さない。
5. VM 再起動やスリープでサーバーが死んでいたら、同じ shell_id で起動し直し、`browser_preview` を再登録する。プレビューは VM の停止で無効になる。

## 避けるべき操作

- `nohup <server> &` や `setsid bash -c '<server>'` によるデーモン化。起動直後に落ちても対話の履歴に出力が残らず、原因を追いにくい。
- `pkill -f <アプリ名>`。`-f` はコマンド列全体にマッチし、`bash -c 'pkill -f ...'` を実行するラッパー自身のコマンド列にもマッチして、新しく起こしたプロセスまで殺すことがある。

## 原則

- サーバーの起動・ログ・停止を一つの shell_id に集約する。
- `dotnet run` のように起動時に自動でビルドするコマンドは、kill → build → run に分割しない。
- プレビューが見えないと言われたら、まずポートの生存を `curl` で確認し、死んでいれば再起動と `browser_preview` の再登録をセットで行う。
