# 子プロンプト定型

子へ渡すプロンプトの骨格。計画フェーズと実装フェーズの両方で使う。
`<...>` は対象ごとに埋める。
リポジトリ固有の規約（仕様の正となる文書、廃止用語、文体スキル、禁止する git 操作、lint・typecheck・test のコマンド）は共通規約の節にまとめ、全子へ同じ内容を付ける。

## 計画子

```
あなたはリポジトリ <owner>/<repo> での監査計画を担当する Devin セッションである。
対象項目は「<項目名>」である。下記の証拠は第一走査で得たものだが、行番号ずれや誤検出がありうるため、着手前に現行 main で自分でも対象箇所を確認し、対象の範囲を深く走査して計画書を作成する。

## 証拠
<第一走査で得た証拠：ファイル、行番号、観測した症状>

## 計画書に含めるもの
- 対象の確定した範囲と、変更しないもの
- 自律適用で進められる修正と、仕様・ユーザー向けの判断が要る要協議事項（各項目に ID と推奨案を付ける）
- 実施手順と受け入れ条件
- 採番が絡む場合は仮採番と明記する

## 対象外の発見
担当項目の範囲外で見つけた問題は、修正も計画もせず out_of_scope_findings に記録して集約へ返す。

## 完了条件
- 計画書はリポジトリ外（~/plans など）に置き、message_user の attachments で共有する
- structured output で報告する：{summary, plan_url, recommendation, requires_discussion, out_of_scope_findings}
```

## 実装子

```
あなたはリポジトリ <owner>/<repo> での作業を担当する Devin セッションである。
添付の計画書ファイルをダウンロードして読み、それを正として実装する。計画書は現行 main で検証済みだが、着手前に自分でも対象箇所を確認すること。

## 共通規約
- 最新 origin/main からブランチを切る。ブランチ名は devin/$(date +%s)-<短い英語スラッグ>。main への直接 push、--no-verify、force push は禁止
- コミット、PR タイトル、本文は日本語。PR は fetch_pr_template でテンプレートを取得してから git_create_pr で作る
- 作業前にリポジトリの規約文書（<AGENTS.md、仕様の正となる文書>）を読む
- 日本語文書を書く・直すときは文体スキルを呼び出す
- コードを変えたら <lint・typecheck・test のコマンド> を実行してグリーンを確認する
- PR 作成後は CI を監視する。Devin Review から指摘が来たらレビュートリアージの作法に従い、実バグは直し、意図的挙動・スコープ外は根拠を書いて返信して解決する
- 複数の子セッションが別トラックで並行して PR を作っている。自分の担当ファイル以外には一切触れないこと。兄弟 PR が先にマージされて競合したら、最新 origin/main にリベースして競合を解消する（解消は自分の担当ファイルに限る）

## 完了条件
- structured output で報告する：{summary, pr_url, pr_number, ci_status, notes, blockers}
- その後、最後の行動として devin_session_interact(action="sleep", session_id=<自分の devin_id>) を呼んでセッションを寝かせる
```

## 注意

- 計画書は `upload_attachment` で URL を取得し、実装子のプロンプト末尾に `ATTACHMENT:"<url>"` マーカーを付けて渡す。
- 実装子への自己 sleep 指示は同時起動スロットを即時解放するためのものである。ワークフローの `agent()` 経由では `suspended` が失敗扱いになる点に注意する。詳細は `parallel-child-implementation` の「運用上の注意」を参照。
