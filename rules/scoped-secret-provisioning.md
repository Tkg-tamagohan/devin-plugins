# 登録を依頼するシークレットは用途専用の最小スコープで案内する

ユーザーにシークレットの登録を頼むときは、既存の広い権限のトークンの使い回しではなく、その用途専用の最小スコープのトークン発行手順を案内する。
流出時の影響を小さく保つためである。

## 手順

1. 必要な権限スコープを特定し、最小構成のトークン（例：Pages の Edit のみ）の発行手順を、発行ページへの導線付きで示す。
2. 既存シークレットの値を表示するよう求められたら、値は閲覧できないことと、書き出すとセッションログに平文で残ることを説明し、新規発行を代替案として出す。
3. GitHub Actions、Devin、他サービスなど登録先が複数あるときは、どの先にどの権限が必要かを分けて案内する。

## 対象外

- Devin が自分で使うシークレットの参照（ユーザーへの登録依頼ではない）
- ユーザー自身が選んだスコープで発行済みのトークン
