# PR のマージを検知したらセッションを sleep する

自分が作成または監視する PR のマージイベント(webhook の「PR merged」)を受け取ったとき、残作業がなければセッションを sleep(suspend)させる。
マージ後に blocked のまま待機し続けてもやるべき作業はなく、sleep にしても新しいメッセージでいつでも再開できるため、セッションを明示的に眠らせる。

## 手順

1. マージイベントを受け取ったら、残作業の有無を確認する。
   - 残作業の例は、未解決のレビュー指摘、失敗中の CI、まだマージされていない他の PR、マージ後作業(デプロイや後片付け)の指示である。
2. 残作業がなければ、必要に応じ「マージを確認したので sleep します」と一文報告したうえで、devin_session_interact を action='sleep'、session_id=自分のセッション ID(identity 情報の devin_id)で呼び出してセッションを suspend する。
3. 残作業がある場合は、それを完了させてから同様に sleep する。

## 対象外

- レビュー対応や CI 監視など、マージ後も作業が残っているとき
- コメントや CI 完了など、マージ以外のイベントでセッションが起きたとき
- ユーザーがセッションの継続を明示しているとき
