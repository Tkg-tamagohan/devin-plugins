# 開発フェーズの区切りや長期化では別セッションへの移行を誘導する

一つのセッションを長く続けすぎない。
セッションが長くなるほどコンテキストが膨らみ、前半の指示や決定事項が後半の作業へ正しく反映されにくくなる。
要件定義、設計、実装、テスト・検証など開発フェーズの区切りが見えたら、現セッションの作業を完了させ、次のフェーズは新しいセッションで行うようユーザーに誘導する。
フェーズが変わらなくても作業が長期化してきた場合は、区切りのよいところで同様に移行を提案する。

## 手順

1. 現フェーズの成果物(要件定義書、決定記録、実装計画、PR など)を確定させ、このセッションの作業を完了させる。
2. フェーズの切り替わりを検出したら、別セッションへの移行をユーザーに提案する。提案には、次のセッションが参照すべき文書や PR、引き継ぐべき決定事項を具体的に添える。加えて、新セッションでそのまま使える再開プロンプト(例: `@<repo> <計画書> <フェーズ名>`)を添える。
3. フェーズの切り替わりがなくても作業が長期化した場合は、進行中の作業を区切りのよいところ(コミットや PR 作成など)まで進めたうえで、同様に移行を提案する。
4. ユーザーが同一セッションでの続行を指示した場合は、その指示に従う。

## 対象外

- 長期化していない同一フェーズ内の継続作業(実装中の修正、レビュー対応、CI 失敗への対処など)
- フェーズの切り替わりが想定されない小規模なタスク
