# 開発フェーズの区切りや長期化では別セッションへの移行を誘導する

一つのセッションを長く続けすぎない。
セッションが長くなるほどコンテキストが膨らみ、前半の指示や決定事項が後半の作業へ正しく反映されにくくなる。
開発フェーズの区切りが見えたら現セッションの成果物を確定し、次のフェーズは新しいセッションで行うようユーザーに誘導する。

## 手順

1. 現フェーズの成果物(要件定義書、決定記録、実装計画、PR など)を確定させ、このセッションの作業を完了させる。
2. 別セッションでの実行を前提に計画書やプロンプトを作成した場合、短い了解だけでは現セッションでコード変更に着工しない。
   現セッションで実装してよいか、未決事項の回答とあわせてユーザーへ確認する。
3. フェーズの切り替わりを検出したら、別セッションへの移行をユーザーに提案する。
   - 提案には、次のセッションが参照すべき文書や PR、引き継ぐべき決定事項、およびそのまま使える再開プロンプト(例: `@<repo> <計画書> <フェーズ名>`)を添える。
   - 引き継ぎが PR のマージ後をまたぐ場合(特に head ブランチ自動削除が有効なリポジトリ)は、作業ブランチ名だけで手順を組まず、マージ後の基準点(`main` やタグ)と新規ブランチでの追従 PR 手順を明記する。
4. 複数セッションで同一リポジトリを分別実行するとき、後続セッションは未コミット差分やシンボル出現だけで先行完了とみなさず、先行コミット、先行 PR マージ、またはユーザーの完了連絡を起点にする。
   未確定の間は非依存タスクのみ先行するかユーザーへ確認する。
5. フェーズの切り替わりがなくても作業が長期化した場合は、コミットや PR 作成など区切りのよいところで同様に移行を提案する。
6. ユーザーが同一セッションでの続行を指示した場合は、その指示に従う。

## 対象外

- 長期化していない同一フェーズ内の継続作業(実装中の修正、レビュー対応、CI 失敗への対処など)
- フェーズの切り替わりが想定されない小規模なタスク
