# テストは仕様から作成し、ID を振って結果を表で報告する

テストコードを書くときは実装ではなく文書を根拠にし、テストケースには ID を振って結果を表で報告する。
実装から期待値を逆引きしたテストは、実装のバグまで正しい挙動として固定してしまう。

## 仕様や要件から作成する

- テストは実装コードの挙動をなぞるのではなく、要件定義や仕様書などの文書を根拠に作成する。
- 実装と文書が矛盾しているときは、どちらを正とするか自分で推測せず、ユーザーに確認する。

## ID を振って結果を表で報告する

- テストケースを作成するときは、対象を表す短い識別子と連番の組み合わせ(例: `AUTH-01`)で ID を振って管理する。
- テスト実施後は、テスト項目一覧とテスト結果を表にまとめて表示する。
- 失敗したケースは追加で抽出し、改善案とあわせてユーザーに提示する。

## 対象外

- テストコードの作成も実施も伴わない作業
