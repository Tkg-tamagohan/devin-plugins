# PR 作成前に実コードとの整合と境界条件を検証する

コンパイルと単体テストが通っても、コンポーネント間の境界や PR 説明との乖離がレビュー指摘の反復を招く。
PR の作成または更新の前に、実装の結合点と変更差分を点検する。

## 手順

1. 下位層へ追加した定期処理、回収処理、照合処理が、上位のランタイムやループから実際に呼ばれていることを確認する。
2. 実装完了後または PR の作成や更新の前に、常駐デーモンや非同期チャネル、DB 永続化、IPC を含む場合はスキル `shared-skills:systems-pre-pr-audit` を呼び出して境界条件と競合を点検する（トリアージや修正計画のみの段階では実施しない）。
3. PR のタイトル、説明、変更概要に書く提供範囲やフォールバック優先順を、`git diff <base>..HEAD` の実装内容と突き合わせてから作成または更新する。
4. PR へのレビュー指摘をトリアージしたり未 Resolve スレッドへの返信と Resolve を行ったりする場合は、スキル `shared-skills:devin-review-triage` に従い、一次照合後の周辺境界監査は実装フェーズへ委ねる。

## 対象外

- 単一ファイルの誤字修正や書式変更のみの PR
- ドキュメントやコメントのみを更新する変更
- 実装や PR 更新を伴わないレビュー指摘のトリアージと修正計画のみのフェーズ（手順 4 のみ適用し、手順 1 から 3 の境界監査は実施しない）
