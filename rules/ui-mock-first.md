# UIツールはユーザー確認をテストに先行する

ユーザー操作を伴うUI系のツールや画面を開発した場合、テストを実施する前にモックまたは起動可能な実装をユーザーに実際に触ってもらうことを義務とする。
UIの見た目や操作性の問題は実装後のテストでは発見が遅れるため、早期にユーザーの確認を得て手戻りを防ぐ。

## 手順

1. モックまたは実装をDevinのVM上で起動し、ブラウザプレビューで公開する。ユーザーはVMのlocalhostに直接アクセスできないため、プレビュー経由で操作してもらう。
2. ユーザーに操作してもらい、見た目と操作性についてフィードバックを得る。
3. フィードバックを反映してから、テストの作成・実施に進む。

## 対象外

- ユーザー操作を伴わないUI(表示のみの画面、CLI出力など)
- UIを持たないツール・ライブラリの開発
